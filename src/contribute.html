Join our scientific advisory team

EvolventAI invites Earth scientists to join the advisory team. We would value your judgment on which questions matter in your field and what evidence an agent would need to answer them well.

  • Recommend research directions and difficult problems worth exploring.
  • Review whether tasks preserve the substance and complexity of real research.
  • Help establish the experiments and evidence needed to accept a result.

You can focus on scientific advice; the engineering team can help with data, software and evaluation code. If you or members of your group would like to develop a task, we would be glad to work with you on it.

What makes a good starting point?

A good starting point is a result your current method cannot explain, or a method that fails on a different dataset. Tell us why the problem matters and what has already been tried.

Already have research materials?

You can add links to data, code, papers or existing experiments in the form. For a complete task, we will work together on the environment, reference experiment and scientific checks.

From a research idea to an evaluation

  1. Recommend a question. Start with a few sentences; add a paper or materials link if you have one.
  2. Develop together. Agree on the scope, prepare the domain environment and build the reference workflow.
  3. Refine and evaluate. Researchers assess the question and its reference results; engineers run the task, and frontier-agent trials show where the difficulty lies.

A complete Harbor task contains instruction.md, task.toml, environment/, solution/ and tests/. These hold the research assignment, software and data, a reference experiment and the scoring program.

Contribute a complete research task

If you have the data and experiments ready, contribute a complete Harbor task. Include the research assignment, a working environment, a reference experiment and the code that scores the result.

  1. A precise assignment. State the scientific question, available inputs, tools, required outputs and acceptance criteria in instruction.md.
  2. A working domain environment. Provide task.toml and environment/ with the required software, model settings, documentation and a runnable baseline. Explain where the data come from, how to obtain them and their terms of use.
  3. The reference experiment and scoring program. Implement solution/solve.sh and tests/test.sh. Use research/ to explain the scientific background, expected research files and data sources. The reference solution runs in the evaluation environment.
  4. A scientific rubric and completed runs. Define a 100-point rubric around the scientific result, the experiments behind it and performance on new cases. Include actual reference runs and examples illustrating full, partial and zero credit. Completion requires 90 points overall, 80% in each dimension and all core research requirements.

Add a repository or archive link to the form above, with the task revision and run records. Large datasets can stay in versioned storage with retrieval instructions. The short proposal route remains open to anyone who wants help developing a task.

A few practical questions

Do I need a finished container?

Not for an initial idea. You can start with a question and develop it with us. A complete task submission does require a reproducible environment, reference solution, verifier and run evidence.

Can a task come from unpublished work?

Yes. Begin with a short description and the materials you are comfortable discussing. Agree on access and publication with the team before sharing the complete research package.

What would an advisor do?

Help select important and difficult problems, review scientific assumptions and evaluation criteria, and interpret results. The project team handles day-to-day engineering and coordination.

How are contributions recognized?

We record task authorship, engineering, review and advisory contributions. Public attribution and paper contributions are agreed according to the work involved.
